# 安克录音豆 × 豆包工作 2.0 产品策划文档（内部评审稿）

> **一句话提案：**
>
>  把安克 AI 录音豆从「飞书妙记的外设麦克风」升级为「豆包工作的随身 Agent 入口」—— 录音结束后不止产出纪要，而是由豆包工作结合飞书上下文自动给出待办、跟进、归档等动作建议，经用户确认后直接执行，补齐「记录 → 理解 → 执行 → 回流」价值链。

**文档性质：** 内部产品策划 / 立项评审材料（草案），用于方向与范围对齐，非已批准的研发承诺。文中 2.0 方案均为产品建议；硬件与 1.0 现状为公开可查事实，豆包工作能力以内部资料为据，均在附录列出口径。

**拟请决策：** ① 是否立项联合开发 2.0（P0 软件闭环）；② 三方（安克 / 飞书妙记 / 豆包工作）数据、品牌与商务分工的谈判授权；③ P0 联合项目组的资源投入与 owner。

# 1. 决策摘要

## 1.1 我们要推动的决定

与安克创新联合定义录音豆 2.0：现有 D3200 硬件通过固件与 App 升级，新增与豆包工作的全链路打通，让线下对话（客户拜访、线下会议、移动访谈等会议软件覆盖不到的场景）成为豆包工作 Agent 可理解、可执行、可沉淀的上下文。本期推动的是**软件 2.0（P0）**，硬件是否改款推迟到 P2 凭数据决策。

## 1.2 本期范围（P0 建议）



* 设备可绑定豆包工作账号，与现有飞书妙记绑定**并存而非替代**，1.0 用户体验不受损；

* 录音结束后在豆包工作生成「Agent 任务卡片」：纪要 + 建议动作清单，关联日历、参会人与项目上下文；

* 确认后执行闭环：创建飞书任务、更新云文档、生成消息 / 邮件草稿、写入多维表格；

* 豆包工作客户端内的设备管理与录音历史入口。

## 1.3 明确不做（本期后置）



* 不做新硬件、不改工业设计与拾音方案（P2 再论证）；

* 不做无确认的自动外发 / 自动改共享数据，Agent 动作默认人工把关；

* 不做企业设备纳管、强制采集等组织级能力（P1）；

* 不碰海外版模型与数据方案（安克海外版现搭载 GPT，P2 再议）。

## 1.4 核心判断（结论先行）



1. **赛道成立且正在变天：** AI 录音硬件已被 PLAUD 验证，行业领头羊正从「记录 + 总结」走向「Agent 直接办完后续工作」；国内钉钉录音卡片靠组织级模式拿到销量第一。录音硬件是各家 AI 办公产品争夺**线下上下文入口**的前哨。

2. **1.0 的价值链断在我们最该接的地方：** 1.0 止于妙记纪要，而豆包工作的核心能力恰好是「理解上下文 → 调用飞书工具 → 把事做完」。两者拼合才形成闭环，目前中间没有通路。

3. **时机窗口特殊：** 飞书团队与产品已整体并入豆包业务线、飞书定位为豆包工作的「上下文数据基座」，组织上第一次具备把硬件合作从飞书侧平滑延伸到豆包工作侧的条件；但豆包工作 8 月底才发布、设备接入能力尚需新建，宜软件轻启、快速验证。

# 2. 背景：1.0 现状与市场信号

## 2.1 1.0 产品现状（事实）

安克 AI 录音豆于 2026 年 1 月 19 日由安克创新与飞书联合发布，国内售价 899 元；其海外版为 soundcore Work AI Voice Recorder（型号 D3200），2025 年 11 月先行发布，搭载 GPT、集成于安克自研 soundcore App，国内版则由飞书提供软件 AI 适配与服务。



| 维度   | 1.0 现状                                                                                                                |
| ---- | --------------------------------------------------------------------------------------------------------------------- |
| 硬件形态 | 直径 23.2mm 硬币大小磁吸纽扣，可夹戴或吸附于电脑 / 手机；双全指向 MEMS 麦克风，有效收音半径 5 米，自研多通道降噪；8GB 存储约 250 小时音频；含充电舱总续航 32 小时以上，快充 10 分钟可录音 2 小时。 |
| 软件承接 | 飞书提供 ASR 语音识别、声纹（说话人）识别、实时转写与翻译、实时 AI 总结、智能纪要；海外版由 GPT 驱动。                                                            |
| 使用流程 | 飞书 App 扫包装二维码，或在「妙记 → 我的设备 → 添加设备」完成绑定；设备以会话形态出现在飞书消息列表；按键开始 / 结束（震动 + 指示灯反馈），录音自动上传飞书妙记，生成带说话人时间线的逐字稿与智能纪要。          |
| 数据归属 | 内容默认沉淀在个人飞书妙记，偏个人使用（内部行业讨论中多位使用者反馈「基本是个人场景，类似 PLAUD」）。                                                                |
| 合作性质 | 据 36 氪报道，该产品并非为飞书全新研发，而是成熟硬件在国内的 AI 生态适配；安克同时与微软等探索其他 AI 生态合作，全球化方案并不绑定单一伙伴。                                          |

## 2.2 市场与竞争信号



* **赛道被验证且利润可观：** PLAUD 创始人在福布斯访谈中称其 2025 年化收入接近 2.5 亿美元，利润率被类比为 iPhone 级；其可穿戴产品 NotePin / NotePin S 定价约 1,199–1,399 港元，支持 112 种语言转写、上万种总结模板，硬件之外按月订阅 AI 服务。

* **行业正跨过「纪要」这一站：** PLAUD 最新发布的 AI 耳机已主打「录音之后 Agent 直接连接邮箱、日历、云盘和文档，把后续工作顺手办了」，叙事从记录、理解延伸到执行 —— 这正是 2.0 要占的位置。

* **国内是组织级打法的较量：** 钉钉 2025 年 8 月率先推出录音卡片（后随千问办公品牌调整），在内部行业讨论中被多位嘉宾认为国内销量最高；其设计逻辑是录音内容**默认归企业所有**，面向销售、客服、咨询等强沟通工种做工作内容强制线上化。企业微信则与得力合作推出录音硬件。

* **对 1.0 的评价两极：** 多位内部行业讨论参与者认为「飞书录音豆体验最好」，但出货量不及钉钉卡片，原因除飞书与钉钉的客群基数差距外，还包括录音豆偏个人场景、缺少组织级数据闭环。

* **战略共识：** 内部分析材料判断，AI 办公的核心壁垒是底层模型与企业上下文数据，「各家均在通过 AI 录音硬件补充上下文获取渠道」；IM 不再是唯一主入口，Agent 优先成为行业共识。

## 2.3 1.0 的价值链断点

1.0 的完整体验是：戴上 → 按键 → 拿到妙记纪要。**纪要之后，价值链就结束了**—— 销售要自己回忆客户承诺并录入 CRM，项目经理要手动把决策和待办搬进任务系统，访谈者要把逐字稿另存后再喂给写作工具。录音内容既不会触发任何 Agent 动作，也不会在下次协作中被自动调用。对豆包工作而言，这意味着一块高质量、高黏性的线下上下文来源，目前停在「文档仓库」里。

# 3. 问题与机会

## 3.1 用户问题



| 目标用户             | 具体情境与受阻行为                                                        | 当前替代方式与成本                                          |
| ---------------- | ---------------------------------------------------------------- | -------------------------------------------------- |
| 销售 / 咨询 / 客户成功   | 客户现场、展会、饭局等线下沟通后，需要回忆承诺、整理拜访纪要、录入客户表格、发跟进消息；遗漏与拖延最常发生在这段「会后一小时」。 | 凭记忆和笔记事后补录，CRM 填写率低；用手机录音还要回办公室整理，电话 / 消息通知还会打断录音。 |
| 项目经理 / 团队负责人     | 线下工作坊、走廊会、1v1 没有飞书会议录制，决策与待办靠手记，回到工位再手动建任务、更新项目文档。               | 手动搬运，待办指派滞后、责任人不清。                                 |
| 内容创作者 / 研究员 / 记者 | 移动采访、调研后面对数小时逐字稿，整理成文章 / 报告 / 脚本耗时巨大。                            | 把妙记逐字稿导出再投喂其他 AI 工具，上下文与素材割裂。                      |
| 泛知识工作者           | 通勤、临时沟通中的灵感与决定散落各处，难以进入自己的任务与知识库体系。                              | 手机备忘录、微信文件传输助手，事后不再回看。                             |

需要说明：以上问题强度目前主要由公开测评、内部行业讨论与 1.0 用户反馈间接支持，尚缺乏我方自有用户的行为数据；P0 阶段应以埋点和访谈完成验证（见第十章）。

## 3.2 豆包工作的战略机会



1. **补上 Agent 的「线下感官」。** 豆包工作已能继承飞书聊天、文档、日程、妙记等线上上下文并自主执行任务，但会议软件之外的线下对话仍是空白。录音豆是成本最低、佩戴最无感的线下采集入口。

2. **把 1.0 的存量硬件变成 Agent 的分发渠道。** 1.0 已上市、已有口碑与安克渠道投入；软件升级即可让这批设备成为豆包工作的获客触点，硬件由安克承担库存与供应链风险。

3. **组织条件首次成熟。** 飞书产品团队与 Aily 已整体并入豆包业务线，飞书被定位为豆包工作的数据与权限基座，妙记本身已是豆包工作可读的上下文类型 ——1.0 的合作资产可以顺势承接，而不必另起炉灶。

4. **个人与企业两条腿走路。** 1.0 占据了个人好口碑，P1 补上企业模式后可同时对标 PLAUD（个人）与钉钉卡片（组织），避免在组织级市场缺席。

## 3.3 不行动基准（如果不做 2.0）



* **对用户：** 纪要之后的手动成本不变，录音豆长期只是「更好用的妙记麦克风」，难以支撑 AI 订阅溢价；

* **对豆包工作：** 线下上下文入口被钉钉 / 千问、PLAUD 等持续占据，Agent 在销售外访、线下会议等场景「没有素材可用」；

* **对合作关系：** 安克是多生态合作策略，国内合作若停留在一次性适配，其后续硬件（耳机等）与 Agent 能力可能优先对接其他伙伴；

* **代价对照：** 不做并非零成本，只是把入口红利让给竞品；而行动的主要投入是软件通路建设，不压硬件库存。

# 4. 产品定位、目标用户与场景

## 4.1 产品定位

> **定位陈述：**
>
>  录音豆 2.0 是豆包工作的
>
> **随身 Agent 入口**
>
> —— 以无感佩戴的硬件捕捉线下对话，以飞书妙记为转写、存储与权限底座，以豆包工作为理解与执行引擎，让每一次线下沟通结束时，待办已建好、跟进已起草、结论已归档。

**一句话差异：** PLAUD / 1.0 帮你「记住」会议，2.0 帮你「办完」会议之后的事；钉钉卡片替组织「盯住」员工，2.0 在个人信任体验之上提供可选的企业模式。

## 4.3 个人模式与企业模式

1.0 的产品基因是「无感、可信、属个人」，钉钉卡片的基因是「组织所有、强制采集」。2.0 不照搬单一模式，而是同一设备支持两种模式、绑定时明示，P0 先交付个人模式，P1 交付企业模式。



| 维度    | 个人模式（P0，默认）                  | 企业 / 团队模式（P1）                     |
| ----- | ---------------------------- | --------------------------------- |
| 设备与账号 | 个人购买、绑定个人飞书 / 豆包账号           | 企业采购或员工设备纳管，由管理后台配置策略             |
| 数据归属  | 归个人，延续 1.0 与 PLAUD 式体验       | 工作场景录音按策略归企业，明确空间与留存期；私人场景可保留个人模式 |
| 上下文范围 | 个人有权访问的飞书内容与个人记忆             | 叠加组织架构、客户 / 项目空间、企业知识库，严格继承飞书 ACL |
| 典型价值  | 个人提效、创作与知识管理，拉动 C 端订阅        | 销售 / 客服 / 咨询等团队的过程数字化与管理可见性       |
| 合规设计  | 录音指示灯 / 提示不可关闭，依赖佩戴者自行告知     | 组织级录音告知模板、员工知情流程、审计日志、数据删除与导出规则   |
| 商业化   | 硬件收入 + 豆包工作个人订阅（68 元 / 月起档位） | 企业批量采购 + 豆包工作企业版额度包               |

## 4.4 成功标准（口径先行，目标值待基线校准）

以下指标用于定义「2.0 是否成立」，当前无基线数据，P0 上线前先完成埋点，上线后以 4–8 周数据校准目标值，**不在本文档承诺提升幅度**。



| 层级       | 指标口径                                                      | 回答的问题                |
| -------- | --------------------------------------------------------- | -------------------- |
| 硬件活跃     | 设备绑定豆包工作账号比例；绑定用户周均录音天数、周均录音段数                            | 硬件用户是否真的进入新链路        |

# 5. 方案选项与推荐

以下四个选项按相同口径比较；比较基于当前已知能力与公开信息，投入规模为相对判断，需立项调研后细化。



| 选项                | 内容                                     | 投入 / 速度           | 体验闭环与壁垒                                  | 主要风险                         |
| ----------------- | -------------------------------------- | ----------------- | ---------------------------------------- | ---------------------------- |
| A 维持 1.0          | 仅持续优化妙记转写与纪要，不接豆包工作                    | 最低 / 最快           | 无闭环；无壁垒                                  | 线下入口被竞品占据，安克合作边缘化            |
| B 轻对接             | 不做硬件级整合，仅在妙记内增加「交给豆包工作处理」入口，复用现有上下文能力  | 低 / 快（约一个 App 版本） | 半闭环；链路割裂、无实时能力、无企业模式，易被复制                | 验证不了软硬一体价值，可能得出「需求不成立」的假阴性结论 |
| **C 全链路 2.0（推荐）** | 三方联合定义：设备直连豆包工作任务通道，个人模式先行、企业模式跟进，分期交付 | 中高 / 软件先行，无需等硬件   | 完整闭环；「线下感官 + 飞书上下文 + Agent 执行」三位一体，迁移成本高 | 三方协调成本；设备接入通路需新建；token 成本待测算 |
| D 自研硬件            | 豆包工作自研录音硬件，不依赖安克                       | 最高 / 最慢（重资产、长周期）  | 可控性最高，但供应链、拾音、渠道均非我方能力圈                  | 重复安克已验证的硬件投入，且破坏现有合作         |

**推荐选项 C，并以选项 B 的能力作为 P0 的最小子集先行灰度**—— 若设备直连通道排期晚于预期，「妙记 → 豆包工作」转交入口可作为过渡方案先上线收集数据，但产品目标与验收仍按 C 的闭环定义，避免把过渡态当成终态。推荐 C 的代价是：需要承担一次三方联合项目的协调成本，并新建豆包工作侧的设备接入能力；这两项恰恰是形成壁垒的一部分，竞品的跨生态连接器体验已被证明「和亲儿子差距很大」。

# 6. 2.0 产品方案（推荐项展开）

## 6.1 端到端流程



![图 2 2.0 端到端流程（泳道视图）：覆盖会前上下文预载、录音、上传、Agent 理解、人工确认、执行到归档回流；虚线框为 P1 能力，其余为 P0](https://aka.doubaocdn.com/s/fmsi2wr8Ia)

流程的三个设计要点：



1. **上下文在录音前就位，而非录音后补救：** 用户授权后，Agent 根据日历预载本次沟通的对象、项目与历史资料，纪要与动作建议从第一分钟起就有业务背景；

2. **人始终掌握「执行闸」：** Agent 产出的是待确认的动作卡片，对外发送、修改共享数据等动作必须本人确认；仅低风险动作（如创建私人任务）可由用户预先授权自动执行；

3. **异常路径显式化：** 无网络缓存补传、未匹配日历手动选场景、转写低置信度标记校对、动作失败可重试或转人工，不把不确定性悄悄吞掉。

## 6.4 个人 / 企业双模式的数据与合规设计



* **录音告知不可妥协：** 硬件指示灯与震动反馈延续 1.0 设计，不提供「静默录音」模式；企业模式由组织提供告知话术与制度配套，产品不替企业规避告知义务；

* **归属在绑定时明示：** 个人设备绑定个人账号即归个人；企业纳管设备在激活时向使用人明示数据归属、采集范围与留存周期；

* **权限不越界：** Agent 能理解的内容严格不超过使用人本人的飞书权限，管理者不能通过设备获得其本无权查看的内容；

* **删除与导出：** 个人模式支持录音与派生内容的彻底删除；企业模式遵循组织留存策略并向员工明示；

* **海外数据：** P0/P1 仅涉及国内环境，海外数据跨境与模型选型不在本期范围。

# 7. 分期路线



![图 3 分期路线图：P0 打通 Agent 闭环（个人模式）、P1 组织与场景（企业模式 + 场景工作伙伴）、P2 入口与生态（硬件交互升级与开放）；含各期关键依赖与进入条件](https://aka.doubaocdn.com/s/LO0fPl4QUq)

各阶段的进入条件是硬门槛：P1 必须以 P0 闭环行为数据为依据，P2 硬件改款必须以企业模式的留存与付费验证为依据，避免在未验证「记录 → 执行」价值前投入硬件重资产。

**分期要点（与上图对应）：**



* **P0・软件 2.0｜打通 Agent 闭环（个人模式）：** 双绑定并存、录音后 Agent 任务卡片、日历 / 参会人 / 项目上下文关联、五类确认后执行动作、豆包工作客户端设备管理与录音历史入口。**关键依赖：** 豆包工作侧设备接入 / 音频任务通路目前未见成熟协议，需新建；妙记数据接口开放；安克 App 与固件配合升级。**进入条件：** 立项获批；安克、飞书、豆包工作三方数据归属、品牌露出与商务分工书面确认。

* **P1・组织与场景｜企业模式 + 场景工作伙伴：** 企业 / 团队模式（设备纳管、数据归属策略、ACL 继承、审计日志）；录音合规（组织级录音告知策略、留存与删除规则）；实时模式（实时转写增强、实时翻译、Agent 实时要点提示）；场景工作伙伴包（销售拜访、访谈调研、会议、内容创作）；录音内容按权限进入企业知识库，可被知识问答检索引用。**关键依赖：** 企业设备管理（MDM 类）能力、与飞书管理后台 / 权限体系打通、种子企业客户共创。**进入条件：** P0 闭环数据达标（任务卡片采纳率、动作执行完成率等口径见正文）；明确 2–3 家种子企业。

* **P2・入口与生态｜硬件交互升级与开放生态：** 硬件交互（语音唤醒、与 Agent 简短对话、TTS 回放）；与 soundcore 耳机等安克音频设备协同（听 + 说 + 录）；豆包工作硬件接入协议开放（录音设备、耳机、会议音箱）；海外版方案（安克全球渠道 + 豆包国际 / 当地合规模型与数据方案）。**关键依赖：** 硬件改款投入与 BOM 论证、端侧语音 / 低功耗链路、海外合规与模型授权。**进入条件：** P1 企业模式验证留存与付费、硬件改款 ROI 成立、安克全球产品路线对齐。

> **硬件节奏判断：**
>
>  1.0 硬件（D3200：双麦 5 米拾音、8GB 约 250 小时存储、含充电舱 32 小时续航）能力足以支撑 P0/P1 的软件体验，无改款必要；P2 的语音交互、TTS、网络在线化才构成真实的硬件改款理由，避免重蹈「一代而热、二代乏力」的覆辙。

# 10. 验证计划与下一步

## 10.1 P0 前的最小验证（立项后 2–4 周）



1. **工程可行性 Spike：** 验证设备事件 → 豆包工作任务通道、妙记内容到 Agent 的调用链路与音频时长限制，产出技术结论；

2. **用户证据补强：** 访谈 10–15 名 1.0 活跃用户（覆盖销售、项目经理、创作者），重点问最近一次录音后实际做了哪些手动动作、耗时与遗漏；同时访谈 2–3 家潜在企业客户的管理诉求；

3. **成本模型：** 以典型 30 / 60 / 120 分钟录音测算端到端 ASR + Agent token 成本，确定额度规则；

4. **三方对齐：** 完成数据、品牌、商务分工备忘录。

## 10.2 P0 灰度建议



* 灰度对象：内部员工 + 安克侧种子用户 + 少量飞书企业客户团队，个人模式先行；

* 灰度范围：先开放任务卡片与三类低风险动作（私人任务、个人文档、消息草稿），多维表格写入与企业场景随后开放；

* 继续 / 调整判据：建议动作采纳率与每段录音完成动作数达到内部基线的合理水平（具体阈值在取得 2–4 周基线后由评审会确定）；若采纳率持续低迷，优先回到场景与动作准确性本身排查，而非立即扩张功能。
